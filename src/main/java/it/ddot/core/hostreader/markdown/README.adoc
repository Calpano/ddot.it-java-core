= Markdown Reader
:icons: font

Extensions:: `.md`, `.markdown`
Kind:: `"markdown"`
Parser:: `MarkdownParser`
Reader:: `MarkdownReader`

See link:../../../../../../../../doc/how-to-write-a-reader.adoc[How to Write a Reader] for the general architecture.

== Content Types

[cols="1,1,1"]
|===
| Markdown syntax | Parser callback | Block boundary

| `<!-- ... -->` (multi-line)
| `onHtmlComment`
| Isolated block — subject resets after the comment

| `<!-- ... -->` (on one line, possibly inside prose)
| `onInlineComment`
| Isolated block — only the comment's inner text is read

| ```` ``` ```` ... ```` ``` ```` or `~~~` ... `~~~`
| `onCodeBlock`
| Isolated block — fenced code treated as triples

| `## Title {#id .class}`
| `onSectionAttributes`
| Isolated block — `#id` becomes `Title ..has tag.. id`, `.class` becomes `Title ..has type.. class`

| `- item`, `* item`, `+ item`, `1. item`
| `onListItem`
| No block — the bullet is stripped, subject persists across list items

| Body text
| `onPlainLine`
| No block — subject persists across consecutive plain lines
|===

== Extraction Notes

* HTML comments may be single-line (`<!-- text -->`) or multi-line; the `<!--` / `-->` delimiters are stripped.
* Fenced code blocks are opened by 3+ backticks or tildes; the fence character of the opening line determines the closing fence character (backtick fence is closed by backtick fence, not tilde).
* `onSectionAttributes` fires only for headings carrying `{...}` attribute syntax.
  The reader synthesizes triples from it: the section title is the subject, each `#id` a `has tag` and each `.class` a
  `has type` object. These triples have no source line of their own, so write-back skips them.
* List items: the bullet is stripped before the triple grammar sees the line (else it would leak into the subject)
  and re-applied on write-back; see `structuredtext.ListMarker`.
* `onPlainLine` delivers the raw line; no stripping is applied to body text.

== Pitfall: Headings with inline triple-like syntax

A heading like `## S1 .... O1` contains four dots, which the triple grammar reads as an untyped triple.
Avoid using triple syntax (`..` or `....`) in heading text that should not produce triples.
