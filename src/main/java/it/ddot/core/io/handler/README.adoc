= Package `it.ddot.core.io.handler`
:icons: font
// ddot.it/off

The `ISourceHandler` implementations that connect host readers to triple events.

.Data flow
----
host reader --lines--> StructuredSource2TripleEvents --IDdotEvent--> your ISourceHandler
----

The handlers that put those events into a `Kgraph` (`TripleEvent2Kgraph`, `Source2Kgraph`, `IKgraphSourceHandler`) live in
`it.ddot.core.kbase.io`, in the separate artifact `ddotit-kbase`.

.Contents
Source2TripleEvents:: Turns a stream of source lines into triple events. An adapter over `io.DdotParser` that owns no grammar.
It *buffers*, because a `,,` block, a `!!block` body or an `off` region spans lines and an unterminated one cancels the
triple that opened it. The buffer is flushed at every point where no construct can still be open: resource end, source end,
`resetSubject()` (a structural boundary) and `emitTriple`. Memory is bounded by the largest chunk between two boundaries.
StructuredSource2TripleEvents:: For readers with structural blocks (sections, comments, fenced blocks): `blockEnd()` resets
the subject so continuation does not cross block boundaries.
