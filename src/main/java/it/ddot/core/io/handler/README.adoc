= Package `it.ddot.core.io.handler`
:icons: font
// ddot.it/off

The `ISourceHandler` implementations that connect host readers to triple events, and triple events to a knowledge graph.

.Data flow
----
host reader --lines--> Source2TripleEvents --IDdotEvent--> TripleEvent2Kgraph --> Kgraph
                       \______________ Source2Kgraph _______________/
----

.Contents
Source2TripleEvents:: Turns a stream of source lines into triple events. An adapter over `io.DdotParser` that owns no grammar.
It *buffers*, because a `,,` block, a `!!block` body or an `off` region spans lines and an unterminated one cancels the
triple that opened it. The buffer is flushed at every point where no construct can still be open: resource end, source end,
`resetSubject()` (a structural boundary) and `emitTriple`. Memory is bounded by the largest chunk between two boundaries.
StructuredSource2TripleEvents:: For readers with structural blocks (sections, comments, fenced blocks): `blockEnd()` resets
the subject so continuation does not cross block boundaries.
TripleEvent2Kgraph:: Adds each `IDdotEvent` to a `Kgraph` as a subject -> predicate -> object edge. Node id == text, so
pattern queries hit the SPO index; labels may collide. Source location is recorded on the edge, and the triple's metadata
is stored flat in the edge's `data` JSON, readable via `Kedge.meta()`.
IKgraphSourceHandler:: An `ISourceHandler` that also exposes its `Kgraph`, so a reader can add data beyond triples
(labels, types, inline HTML from the AsciiDoc reader). Split out of `ISourceHandler` to keep that interface graph-free.
Source2Kgraph:: Convenience `IKgraphSourceHandler` chaining `Source2TripleEvents` and `TripleEvent2Kgraph` into one `Kgraph`.
